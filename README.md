# Agentic OS

داشبورد command-center محلی برای Claude Code + vault ابسیدین (`moein brain`) — بازسازی Agentic OS از ویدیوی Chase AI.

## نصب با Setup (سیستم‌های دیگر)

پیش‌نیازها: Windows 10 یا 11، [Claude Code](https://claude.com/claude-code) نصب و لاگین‌شده، و یک vault ابسیدین. Node لازم نیست.

1. `Agentic OS Setup <نسخه>.exe` را اجرا کنید. این فایل را `npm run setup` در پوشهٔ `Setup\` می‌سازد. چون امضای دیجیتال ندارد، ویندوز ممکن است هشدار SmartScreen بدهد؛ روی **More info** و بعد **Run anyway** بزنید.
2. پوشهٔ vault را انتخاب کنید. محل نصب را هم می‌شود عوض کرد؛ پیش‌فرض `%LOCALAPPDATA%\Programs\Agentic OS` است. برای نصب به دسترسی admin نیازی نیست.
3. گزینه‌ها: میان‌بر دسکتاپ، اجرا هنگام ورود به ویندوز، کپی مهارت‌های نمونه در `<vault>\.claude\skills`، و ثبت ابزار `vault-search` در Claude Code. ابزار `vault-search` با خود `Agentic OS.exe` اجرا می‌شود و Node نمی‌خواهد.

- **مسیرها:** خود برنامه در پوشهٔ نصب است. تنظیمات (`config.json`) و داده‌ها (`data\`) به‌طور پیش‌فرض در `%APPDATA%\Agentic OS` هستند و با به‌روزرسانی یا حذف برنامه پاک نمی‌شوند. برای نگه‌داشتن همه‌چیز بیرون از درایو C، پوشهٔ دیگری بدهید: متغیر کاربری `AGENTIC_OS_HOME`، یا فایل `home.txt` کنار exe که مسیر را در یک خط دارد. پوشهٔ نصب را برای داده انتخاب نکنید، چون نصب دوباره آن را کامل پاک می‌کند. فایل‌های موقت، پروفایل مرورگرِ کارت‌های تلگرام (`cache\`) و کش Electron (`electron\`) هم در همین پوشه ساخته می‌شوند، نه در Temp یا AppData.
- **به‌روزرسانی:** Setup نسخهٔ تازه را روی همان پوشه اجرا کنید. تنظیمات قبلی حفظ می‌شوند.
- **حذف:** از Settings ← Apps، یا با `Uninstall Agentic OS.exe` در پوشهٔ نصب. موقع حذف می‌پرسد که تنظیمات و داده‌ها هم پاک شوند یا نه.
- **نصب بی‌صدا:** `"Agentic OS Setup 1.6.0.exe" /silent /vault:"D:\Vault" /dir:"D:\Apps\Agentic OS"`. پرچم‌های اختیاری: `/nodesktop`، `/nologin`، `/noskills`، `/nomcp`، `/nolaunch`. برای حذف بی‌صدا: `/uninstall /silent`.
- skillهای نمونه به ساختار vault خود من (`raw/`، `wiki/`، `index.md`، `log.md`) و خروجی فارسی تنظیم شده‌اند؛ برای vault خودتان ویرایش‌شان کنید.

## اجرا از سورس (توسعه)

پیش‌نیاز: [Node.js](https://nodejs.org) 18 یا بالاتر.

```
npm install                             ← فقط برای اپ دسکتاپ و ساختن exe
start.cmd                               ← فقط سرور، و باز شدن داشبورد در مرورگر (http://127.0.0.1:4747)
app.vbs                                 ← اپ دسکتاپ از سورس
npm run dist                            ← dist\Agentic OS\Agentic OS.exe
npm run setup                           ← Setup\Agentic OS Setup <نسخه>.exe (exe را هم می‌سازد)
```

محل تنظیمات و داده‌ها در `lib/home.js` تعیین می‌شود. اگر در پوشهٔ پروژه `config.json` باشد، همان استفاده می‌شود؛ وگرنه `%APPDATA%\Agentic OS` (همان تنظیماتی که نسخهٔ نصب‌شده استفاده می‌کند). با متغیر `AGENTIC_OS_HOME` هم می‌شود مسیر دیگری داد. `config.json` و `data\` در git نیستند.

برای اینکه routineهای زمان‌بندی‌شده خودکار اجرا شوند، برنامه باید روشن باشد. در نسخهٔ نصب‌شده، «اجرا هنگام ورود به ویندوز» همین کار را می‌کند.

## خودکارسازی و محافظت

- **محافظ سهمیه** (`quotaGuard`): وقتی مصرف ۵ ساعته به `fiveHourMax` (پیش‌فرض ۸۰٪) یا مصرف هفتگی به `weeklyMax` (پیش‌فرض ۹۰٪) برسد، اجراهای خودکار عقب می‌افتند و بعد از ریست پنجره اجرا می‌شوند. در Upcoming با برچسب «عقب افتاد · سهمیه» نمایش داده می‌شوند. اجرای دستی از داشبورد یا tray اول تأیید می‌گیرد. حد محافظ با یک خط عمودی روی نوارهای مصرف مشخص است.
- **اجرای خودکار با فایل جدید** (`watchers`): هر فایل تازه در `raw/` (به‌جز `raw/market`، `raw/research` و `raw/assets`)، ۹۰ ثانیه بعد از آخرین تغییر، مهارت `ingest-source` را اجرا می‌کند. این مهارت فایل را طبق Ingest workflow در `CLAUDE.md` وارد wiki می‌کند. فایل‌های پردازش‌شده در `data/watch.json` ثبت می‌شوند.
- **صندوق خروجی‌ها** (`inbox`): گزارش اجراهای تازه و فایل‌های جدید در `output/`، `raw/market` و `raw/research`، تا وقتی باز یا «خوانده‌شده» شوند. شمار موارد در ویجت و tooltip منوی tray هم دیده می‌شود.
- **مصرف هر مهارت:** تعداد اجرا و هزینهٔ معادل API هر مهارت در ۷ و ۳۰ روز گذشته، از روی `data/runs.json`.
- **ارسال به تلگرام** (`telegram`): نتیجهٔ مهارت‌های `telegram.skills` (و خطاها، اگر `notifyFailures` روشن باشد) از طریق Bot API فرستاده می‌شود. گزارش ابری Market Scan هم پس از همگام‌سازی ارسال می‌شود. ارسال با `curl.exe` و از طریق `proxy` انجام می‌شود، چون تلگرام در ایران مستقیم باز نمی‌شود. اگر ارسال شکست بخورد، پیام در صف `data/telegram.json` می‌ماند و هر ۱۰ دقیقه دوباره امتحان می‌شود.
  1. در تلگرام به `@BotFather` پیام بده، `/newbot` را بزن و توکن را در `config.json → telegram.botToken` بگذار.
  2. به ربات خودت `/start` بفرست. شناسهٔ چت خودکار پیدا می‌شود.
  3. اپ را از tray ببند و دوباره باز کن، بعد در داشبورد روی **TELEGRAM** در اتصال‌ها کلیک کن تا پیام آزمایشی برود.
- **کارت‌های تصویری** (`lib/card`): گزارش‌ها و هشدارها به‌صورت تصویر فرستاده می‌شوند، به شکل نقشهٔ ذهنی، با زبان تصویری groepl/Obsidian-Templates: صفحهٔ سفید، عنوان با خط «نوع | منبع | تاریخ»، باکس مشکی ریشه، شاخه‌های خاکستری، هر بخش یک باکس شماره‌دار، نکته‌های کلیدی با برچسب زرد، و راهنما (Legend) در پایین. درخت از بالا به پایین است تا روی گوشی خوانا بماند. Edge یا Chrome که روی سیستم نصب است صفحه را به‌شکل headless رندر می‌کند (بدون نصب چیز اضافه، فونت Vazirmatn داخل خود صفحه است). گزارش بلند به چند صفحه بریده می‌شود و به‌صورت آلبوم می‌رود؛ برش فقط روی ردیف‌هایی انجام می‌شود که جز شاخه‌ها خالی‌اند، پس هیچ خطی نصف نمی‌شود. دکمهٔ «📝 متن کامل» متن قابل کپی را می‌فرستد. اگر مرورگری پیدا نشود یا `telegram.cards` روی `false` باشد، همان گزارش به‌صورت متن قالب‌بندی‌شده می‌رود.

## نقشهٔ حافظه و نقشهٔ مغز (از چارچوب MAPS)

- **نقشهٔ حافظه:** `MAP.md` در ریشهٔ vault، تابلوی اصلی است: حوزه‌ها را فهرست می‌کند و به `maps/<حوزه>.md` لینک می‌دهد. هر فایل نقشهٔ حوزه شش بخش ثابت دارد: Projects، State، Skills، Memory، Routines، Not here. هر چیزی فقط دو قدم با ریشه فاصله دارد و هر واقعیت فقط یک خانه دارد. هر خط به این شکل است: `- [name](<absolute path>): note`.
- **بررسی خودکار** (`lib/mapcheck.js`، بدون AI): موقع شروع و هر شب ساعت ۰۳:۰۰ اجرا می‌شود. لینک‌های خراب، بخش‌های جاافتاده، طول بیش از حد (۶۰ خط برای ریشه و ۸۰ برای هر حوزه) و صفحه‌های `wiki/projects` بیرون از نقشه را پیدا می‌کند. وضعیتش در Integrations با نام `MEMORY MAP` دیده می‌شود و با کلیک دوباره اجرا می‌شود. اگر مشکلی پیدا کند، به تلگرام هم هشدار می‌دهد.
- **نقشهٔ مغز** (`/brain`): کل سیستم به‌شکل یک گراف: ریشه، حوزه‌ها، پروژه‌ها، یادداشت‌ها و `[[پیوندها]]`، مهارت‌ها، روتین‌ها و اجراها. شش نما دارد: حلقه‌ها، دایره، حوزه‌ها، پیوندها (force)، زمان و مدار. رنگ هر گره حوزه‌اش را نشان می‌دهد، شکلش نوعش را، و اندازه‌اش تعداد پیوندهایش را. با بردن موس روی یک گره، همه‌چیز جز خودش و همسایه‌هایش کم‌رنگ می‌شود. با کلیک، کارتی با گزینه‌های «باز کردن»، «کپی مسیر» و «برو» باز می‌شود. جست‌وجو هم دارد، و با زدن هر حوزه در راهنما فقط آن حوزه نشان داده می‌شود. بدون هیچ کتابخانه‌ای با Canvas ساخته شده.
- **محدودیت‌ها:** هر اجرا با `--max-turns` محدود می‌شود (`skills[].maxTurns` یا `maxTurns`، پیش‌فرض ۴۰). هر اجرا یک خط به `data/runs.log` اضافه می‌کند؛ این فایل فقط اضافه می‌شود و هیچ‌وقت بازنویسی نمی‌شود.
- **تلگرام `/note <متن>`:** متن را بدون AI به یادداشت روزانه، زیر «📥 از تلگرام»، اضافه می‌کند.
- اصول هفت‌گانه در `CLAUDE.md` vault ثبت شده‌اند.

## یادگیری، کیفیت و کنترل از راه دور

- **بازخورد و یادگیری:** کنار «آخرین اجرا» و موارد صندوق خروجی‌ها دکمه‌های 👍 و 👎 هست، با یک یادداشت اختیاری. بازخورد در `.claude/skills/<skill>/learnings.md` ذخیره می‌شود (۴۰ مورد آخر)، و runner به مهارت می‌گوید قبل از شروع آن را بخواند. برای مهارت‌های ابری (اسکن بازار و گزارش صبح)، همان فایل به `learnings/<skill>.md` در ریپوی خصوصی push می‌شود و روتین‌ها قبل از نوشتن آن را می‌خوانند.
- **بررسی کیفیت:** هر مهارت یک فهرست `checks` (معیارهای بله/خیر) دارد. بعد از هر اجرای موفق، Haiku خروجی را با این معیارها می‌سنجد (حدود ۰٫۰۵ دلار و ۱۰ ثانیه). نتیجه به‌صورت «کیفیت ✓» یا «⚠ نیاز به بازبینی» در داشبورد و صندوق دیده می‌شود، و در صورت رد شدن به تلگرام هم خبر می‌دهد. وقتی محافظ سهمیه فعال است، این بررسی اجرا نمی‌شود.
- **نگهبان گزارش‌ها:** در ریپوی خصوصی (`watchdog.yml`): اگر اسکن بازار تا ۰۷:۴۵ یا گزارش صبح تا ۰۸:۴۵ نرسیده باشد، به تلگرام هشدار می‌دهد. با PC خاموش هم کار می‌کند.
- **هشدار سهمیه** (`quotaAlerts`): وقتی مصرف ۵ ساعته از ۷۰٪ یا ۹۰٪، یا مصرف هفتگی از ۷۵٪ یا ۹۰٪ رد شود، به تلگرام پیام می‌دهد؛ در هر پنجره یک بار برای هر آستانه.
- **دستورهای تلگرام** (`telegram.commands`, `lib/tgapp.js`): ربات مثل یک اپ کوچک کار می‌کند. `/start` صفحهٔ خانه را به‌شکل کارت نشان می‌دهد (حلقه‌های مصرف ۵ ساعته و هفتگی، اجراهای امروز، آخرین اجرا و بعدی)، با دکمه‌های مهارت‌ها، صندوق، به‌روزرسانی و راهنما. هر دکمه همان پیام را عوض می‌کند، پیام تازه نمی‌فرستد. از صفحهٔ مهارت‌ها می‌شود هر مهارت را باز کرد و با ▶️ اجرا کرد. دستورها هم کار می‌کنند: `/status`، `/skills`، `/inbox` و `/run <مهارت>` (با `force` از محافظ سهمیه رد می‌شود)، و در منوی کنار جعبهٔ پیام هم دیده می‌شوند. فقط پیام‌های چت خودت پذیرفته می‌شوند. نتیجهٔ `/run` در همان چت فرستاده می‌شود. چون این دستورها روی خود PC اجرا می‌شوند، PC باید روشن باشد.
- **کنترل از گوشی (Remote Control):** دکمهٔ «کنترل از گوشی» در داشبورد یا منوی tray، `claude remote-control` را در vault باز می‌کند. با اپ Claude روی گوشی می‌توانی جلسهٔ تازه شروع کنی یا ادامه بدهی. بار اول باید در همان پنجره `y` بزنی. برای اجرای خودکار با اپ: `remoteControl.autoStart: true`.
- **جلسه‌های Claude Code:** ۱۲ جلسهٔ آخر با عنوان، پروژه، توکن و هزینه، به‌همراه جست‌وجوی متنی در گفت‌وگوها. دکمهٔ «▸ ادامه» جلسه را در ترمینال با `claude --resume` باز می‌کند.
- **پروژه‌ها و جلسه‌های Claude** (`lib/projects.js`، `/api/projects`): در داشبورد و ویجت، همهٔ پروژه‌ها (صفحه‌های `wiki/projects`) و همهٔ جلسه‌های Claude Code این کامپیوتر و کامپیوتر قدیمی (که `~/.claude/projects` آن به این سیستم منتقل شده)، با فیلتر «این کامپیوتر / کامپیوتر قدیمی». کلیک روی پروژه صفحه‌اش را در Obsidian باز می‌کند و کلیک روی جلسه یادداشتی را که برایش در `claude-sessions/` ساخته شده (عنوان، پروژه، پوشه، درخواست‌ها، دستور `--resume`). جلسه به پروژه‌ای وصل می‌شود که پوشه‌اش در `path:` صفحه باشد، یا نامش (یا `aliases:`) در عنوان جلسه بیاید. جلسه‌های خودکار (اجرای مهارت، بررسی کیفیت، sync قدیمی vault) نشان داده نمی‌شوند. کامپیوتر قدیمی با `claudeProjects.oldComputer` تشخیص داده می‌شود: پوشهٔ خانهٔ آن (`homes`) و تاریخ جابه‌جایی (`before`).
- **جست‌وجو در مخزن:** جست‌وجوی BM25 با نرمال‌سازی فارسی (ی/ي، ک/ك، نیم‌فاصله)، که به عنوان یادداشت‌ها وزن بیشتری می‌دهد. همین جست‌وجو به‌صورت MCP (`mcp/vault-search.js`، ابزار `search_vault`) در Claude Code و در اجراهای headless هم در دسترس است. وقتی اپ روشن است، MCP جوابش را از اپ می‌گیرد (جست‌وجوی ترکیبی). وقتی اپ خاموش است، خودش جست‌وجوی کلمه‌ای انجام می‌دهد.
  ```
  claude mcp add vault-search --scope user -- node "<path>\mcp\vault-search.js"
  ```
- **جست‌وجوی معنایی** (`semantic`): یادداشت‌ها با مدل چندزبانهٔ `bge-m3` در یک Ollama قابل‌حمل به بردار تبدیل می‌شوند (`data/vectors.json`). نتیجه ترکیبی است: ۶۵٪ شباهت معنایی و ۳۵٪ امتیاز کلمه‌ای. برای همین پرسش فارسی یادداشت انگلیسی را هم پیدا می‌کند، و برعکس. از سهمیهٔ Claude هم چیزی مصرف نمی‌کند.
  - **Ollama فقط موقع نیاز روشن می‌شود:** موقع جست‌وجو، یا برای به‌روزرسانی شبانهٔ نمایه (ساعت ۰۳:۰۰). پیش از هر جست‌وجو فقط یادداشت‌های تغییرکرده دوباره نمایه می‌شوند.
  - **خاموش شدن خودکار:** بعد از `idleMin` دقیقه بی‌کاری (پیش‌فرض ۵)، Ollama بسته می‌شود. این کار فقط وقتی انجام می‌شود که خود اپ آن را روشن کرده باشد و برنامهٔ دیگری از آن استفاده نکند. اگر برنامهٔ دیگری مدلی در آن بارگذاری کرده باشد، روشن می‌ماند.
  - **مصرف حافظه:** مدل با `keep_alive` یک‌دقیقه‌ای از RAM خارج می‌شود. با خروج از اپ هم Ollama بسته می‌شود. بعد از بستن Ollama، پردازه‌های `llama-server.exe` جامانده از پوشهٔ خودش هم بسته می‌شوند. هر کدام از این پردازه‌ها کل مدل را در RAM نگه می‌دارد.
  - **فقط CPU** (`semantic.gpu: false`، پیش‌فرض): embedding یک پرسش روی CPU حدود ۶۰ میلی‌ثانیه طول می‌کشد. در مقابل، آماده‌سازی GPU (Vulkan) در هر شروع سرد بیش از ۳۰ ثانیه طول می‌کشید.
  - **سرعت در داشبورد:** نتیجه‌های کلمه‌ای (`mode=keyword`) فوراً نشان داده می‌شوند و نتیجهٔ ترکیبی چند لحظه بعد جایشان را می‌گیرد. با focus روی کادر جست‌وجو، مدل از قبل بارگذاری می‌شود (`/api/semantic/warm`).
  - **محل نصب:** همه‌چیز در پوشهٔ خود Ollama می‌ماند: برنامه، مدل‌ها (`modelsDir`) و پوشهٔ home آن.
  - **راه‌اندازی:** نسخهٔ zip ویندوز را از [releases](https://github.com/ollama/ollama/releases) بگیرید و در یک پوشه باز کنید. بعد در `config.json` مقدار `semantic.enabled: true`، `ollamaPath` و `modelsDir` را تنظیم کنید. مدل در اولین استفاده دانلود می‌شود (حدود ۱٫۲ گیگابایت).
- **ساخت مهارت از داشبورد:** دکمهٔ «+ مهارت جدید» یک فرم باز می‌کند: نام، نام فارسی، حوزه، مدل، کاربرد، دستورالعمل، ساعت، روزها و ابزارها. فایل `SKILL.md` در vault و ورودی `config.json` بدون نیاز به ری‌استارت ساخته می‌شوند.

## زبان

فارسی (راست‌به‌چپ، تاریخ شمسی) و انگلیسی. زبان با دکمهٔ **فا / EN** در سربرگ داشبورد عوض می‌شود. این تنظیم سمت سرور ذخیره می‌شود (`data/ui.json`)، پس ویجت و منوی tray هم همراهش عوض می‌شوند. زبان پیش‌فرض در `config.json → language` است و نام فارسی هر مهارت در `skills[].labels.fa`.

## اپ دسکتاپ (Electron)

```
npm install
node node_modules\electron\install.js   ← npm 11 اسکریپت postinstall را بلاک می‌کند؛ این دستور باینری Electron را می‌گیرد (از کش محلی اگر باشد)
app.vbs                                 ← اجرای اپ از سورس (یا npm run app)
npm run dist                            ← ساخت dist\Agentic OS\Agentic OS.exe
npm run setup                           ← ساخت Setup\Agentic OS Setup <نسخه>.exe
```

- **فایل exe:** دستور `npm run dist` هیچ چیزی دانلود نمی‌کند. از همان Electron داخل `node_modules` استفاده می‌کند و فقط زبان‌های en و fa را نگه می‌دارد. آیکن و مشخصات exe را هم با `rcedit` تنظیم می‌کند. اگر برنامه باز باشد، اول با `--quit` بسته می‌شود و بعد از ساخت دوباره باز می‌شود.
- **فایل Setup:** دستور `npm run setup` اول exe را می‌سازد. بعد `scripts/setup/Setup.cs` را با کامپایلر C# که همراه ویندوز است (`.NET Framework 4`) دو بار کامپایل می‌کند: یک بار بدون بار، به‌عنوان حذف‌کننده (`Uninstall Agentic OS.exe`) که داخل پوشهٔ برنامه قرار می‌گیرد، و یک بار با فایل zip برنامه که درونش جاسازی شده، به‌عنوان نصب‌کننده. هیچ چیزی دانلود نمی‌شود و خروجی حدود ۱۲۷ مگابایت است.
- سرور داشبورد داخل خود اپ اجرا می‌شود. اگر سرور مستقل (`start.cmd`) از قبل روشن باشد، اپ فقط به آن وصل می‌شود.
- **پنجره‌ها:** داشبورد کامل، و ویجت شناور همیشه‌رو که قابل کشیدن است و جایش ذخیره می‌شود.
- **بستن پنجره:** پنجره کاملاً بسته می‌شود تا حافظه‌اش آزاد شود. اپ در tray می‌ماند و scheduler روشن است. برای خروج کامل: tray ← Quit.
- **منوی tray (کلیک راست):** باز کردن داشبورد، نمایش یا پنهان کردن ویجت، اجرای skill (با تأیید)، **Start at login** (اجرا هنگام ورود به ویندوز، فقط با tray و ویجت)، و Quit.
- **نوتیفیکیشن:** پایان هر اجرا با هزینه و مدل اعلام می‌شود. کلیک روی آن گزارش را در Obsidian باز می‌کند.
- اگر `app.vbs` از داخل VS Code اجرا شود، متغیر `ELECTRON_RUN_AS_NODE` را خودش پاک می‌کند.

## سبک و سریع

- **پنجره‌ها:** پنجرهٔ بسته و ویجت پنهان از حافظه پاک می‌شوند و دوباره ساخته نمی‌شوند تا وقتی که باز شوند. وقتی پنجره پنهان یا کوچک باشد، صفحه هیچ درخواستی به سرور نمی‌فرستد. با دیده شدن دوباره، یک بار به‌روز می‌شود.
- **tray:** برای به‌روز ماندن هیچ پرسشی به سرور نمی‌فرستد. منو هر بار که باز می‌شود از نو ساخته می‌شود، و tooltip دقیقه‌ای یک بار به‌روز می‌شود. خبر پایان هر اجرا مستقیم از خود سرور می‌آید.
- **سرور:** وضعیت داشبورد سه ثانیه کش می‌شود، چون داشبورد، ویجت و tray همه همان را می‌خواهند. تغییرات اخیر vault یک دقیقه کش می‌شوند، فهرست مهارت‌ها ۱۵ ثانیه، و صندوق خروجی‌ها ۲۰ ثانیه. خواندن لاگ‌های مصرف هم فقط بخش تازهٔ فایل‌ها را می‌خواند.
- **فرایندهای جانبی:** `claude mcp list` ساعتی یک بار اجرا می‌شود (یا با دکمهٔ refresh). Ollama فقط وقتی لازم باشد روشن است.
- **نقشهٔ مغز:** فقط وقتی چیزی در حال حرکت است (انیمیشن، زوم، مدار) دوباره کشیده می‌شود. در حالت ساکن، CPU مصرف نمی‌کند.

## داشبورد

- **5-HOUR / WEEKLY WINDOW:** نوارها درصد واقعی مصرف از claude.ai را نشان می‌دهند؛ همان عددی که `/usage` در Claude Code نشان می‌دهد (`LIMITS · LIVE` در هدر). زمان ریست هم واقعی است.
  - این عدد با لاگین محلی Claude Code (`~/.claude/.credentials.json`) خوانده می‌شود. توکن فقط به `api.anthropic.com` فرستاده می‌شود و هیچ‌وقت به مرورگر نمی‌رسد.
  - توکن‌های مصرفی از لاگ‌های `~/.claude/projects/**/*.jsonl` می‌آیند. سقف توکنی از «مصرف ÷ درصد» حساب و در `data/limits.json` ذخیره می‌شود (با علامت `~`).
  - اگر endpoint در دسترس نباشد (`LIMITS · EST`)، همان سقف ذخیره‌شده یا `config.json → limits` استفاده می‌شود.
- **ROUTINES:** اجراهای امروز در برابر `dailyRunLimit`، که فقط یک محافظ محلی است؛ Anthropic سقف روزانه برای routineها ندارد و فقط سقف ساعتی دارد. کنارش هزینهٔ معادل API امروز نمایش داده می‌شود.
- **CUMULATIVE ACTIVITY** — مجموع تجمعی توکن‌ها در ۳۰ روز (hover برای جزئیات روز).
- **INTEGRATIONS** — از `claude mcp list` (هر ۱۵ دقیقه).
- **LAST RUN / RECENT RUNS** — هر اجرا یک یادداشت در `dashboard-runs/YYYY-MM-DD/HH-MM-<skill>.md`؛ کلیک = باز شدن در Obsidian.
- **SKILLS** — کلیک → prompt قابل ویرایش → `claude -p` headless در vault (`Ctrl+Enter` = اجرا).

## Routineهای ابری

Claude Code Routines در سرورهای Anthropic اجرا می‌شوند، حتی وقتی سیستم خاموش است. خروجی‌شان را در همین ریپو commit می‌کنند.

این روتین‌ها بدون روشن بودن PC کار می‌کنند. خروجی‌شان در یک ریپوی **خصوصی** جدا (`agentic-reports`) ثبت می‌شود و یک GitHub Action هر گزارش جدید را به تلگرام می‌فرستد. این Action هیچ AI ندارد و توکن ربات فقط در GitHub secrets است، پس Claude هیچ‌وقت آن را نمی‌بیند. به همین دلیل یک ایمیل مخرب هم نمی‌تواند Claude را وادار کند داده‌ها را به چت دیگری بفرستد.

| روتین | زمان (تهران) | ورودی | خروجی |
|---|---|---|---|
| Market Scan | ۰۷:۰۷ | وب | `reports/market/DATE.md` |
| Morning Brief | ۰۸:۰۷ | Gmail و Calendar (فقط خواندنی) + گزارش بازار | `reports/brief/DATE.md` |
| Weekly Review | جمعه ۲۰:۳۰ | snapshot vault (شاخهٔ `vault`) + گزارش‌های هفته | `reports/weekly/YYYY-Www.md` |

- مدیریت روتین‌ها: https://claude.ai/code/routines
- **همگام‌سازی:** وقتی PC روشن است، داشبورد هر ۱۵ دقیقه `cloudSync.repo` را fetch می‌کند (یک clone جداگانه در `data/cloud-reports`) و گزارش‌ها را در vault کپی می‌کند: `raw/market/`، `output/briefs/` و `output/weekly/`. این کپی‌ها در صندوق خروجی‌ها هم نمایش داده می‌شوند. git هیچ‌وقت پنجرهٔ ورود باز نمی‌کند.
- ریپوی خصوصی دو secret دارد: `TELEGRAM_BOT_TOKEN` و `TELEGRAM_CHAT_ID`.
- **snapshot vault** (`cloudSync.vaultBranch`): همان تیک ۱۵ دقیقه‌ای، اگر vault تغییر کرده باشد، یک snapshot از کل vault (با تغییرات commit نشده و با رعایت `.gitignore`) را به شاخهٔ `vault` ریپوی خصوصی push می‌کند. برای این کار از یک index جداگانه در `cache/vault-index` استفاده می‌شود و HEAD و index خود vault دست نمی‌خورند. روتین مرور هفتگی vault را از همین شاخه می‌خواند. وقتی این روتین فعال است، `schedule` مهارت weekly-review را در `config.json` حذف کن تا دو بار اجرا نشود.

## انتخاب مدل (model routing)

هر skill یک سطح (`tier`) دارد و هر سطح به یک مدل وصل است (`config.json → models`):

| سطح | مدل | skillها |
|---|---|---|
| `light` | Haiku 4.5 | project-pulse — خواندن و خلاصهٔ ساده |
| `standard` | Sonnet 5.5 | همهٔ مهارت‌های دیگر، از جمله deep-research — جمع‌بندی، نوشتن، تحقیق |
| `heavy` | Opus 5.5 | پیش‌فرض هیچ مهارتی نیست؛ فقط با انتخاب دستی در پنجرهٔ اجرا |

- skillی که `tier` نداشته باشد از `defaultTier` (پیش‌فرض `standard`) استفاده می‌کند؛ `model` مستقیم روی یک skill بر سطح آن اولویت دارد.
- تست vault-cleanup: روی Opus ‏$1.12 و همهٔ مشکلات واقعی را پیدا کرد؛ روی Haiku ‏$0.18 ولی لینک‌های شکسته را ندید — به همین دلیل روی Sonnet است.
- در پنجرهٔ اجرای داشبورد می‌توان مدل را فقط برای همان اجرا عوض کرد (LIGHT / STANDARD / HEAVY).
- مدل هر اجرا در Last Run، ویجت و frontmatter یادداشت اجرا (`model:`) ثبت می‌شود.

## اضافه کردن skill

1. پوشهٔ `<vault>\.claude\skills\<name>\` با `SKILL.md` (frontmatter: `name`, `description`) بسازید — یا در Claude Code از `/skill-creator` استفاده کنید.
2. در `config.json → skills` یک ورودی اضافه کنید:

```json
{ "name": "<name>", "domain": "Research", "tier": "light", "schedule": "09:00", "days": ["sat","sun"],
  "prompt": "Use the <name> skill.", "allowedTools": ["Read", "Glob", "Grep", "WebSearch"] }
```

`schedule` و `days` اختیاری‌اند (بدون آن‌ها = فقط دستی). در prompt می‌توان از `{{date}}`، `{{time}}` و `{{dailyNote}}` استفاده کرد. سرور را ری‌استارت کنید.

skillی که در config نباشد با دسترسی فقط-خواندنی (`Read, Glob, Grep`) زیر دامنهٔ Other نشان داده می‌شود.
